# Agent Project Guidelines: Agent Gateway & Entra Agent ID

## Mandatory Rules for Agent Development

### 1. Strictly Follow `agents-cli` Skills
Always adhere to the Google ADK and `agents-cli` skills suite:
- `google-agents-cli-workflow`: Follow the standard development lifecycle (scaffold $\rightarrow$ build $\rightarrow$ eval $\rightarrow$ deploy $\rightarrow$ observe).
- `google-agents-cli-scaffold`: Use `agents-cli scaffold` commands for project creation, enhancement, and infrastructure.
- `google-agents-cli-adk-code`: Write pure ADK agent code (`Agent`, `Tool`, `App`, `Gemini` models).
- `google-agents-cli-deploy`: Use `agents-cli deploy` for target deployments (Agent Runtime, Cloud Run, GKE).

### 2. Never Hand-Edit Scaffolded Infrastructure Files
Do **NOT** write custom or hand-edited implementations for framework infrastructure files generated by `agents-cli scaffold`. 

The following files must remain pristine and unmodified (or updated exclusively via `agents-cli scaffold enhance` / scaffold templates):
- `fast_api_app.py`
- `agent/app_utils/services.py`
- `agent/app_utils/a2a.py`
- `agent/app_utils/reasoning_engine_adapter.py`
- `Dockerfile`

### 3. Developer Code Boundaries
Developer customization is strictly scoped to:
- `agent/agent.py`: Define `root_agent` using `google.adk.agents.Agent` and `app` using `google.adk.apps.App`.
- `agent/tools/`: Custom Python tool functions and integrations.
- `agent/auth/`: Custom token exchange and credential helpers.
- `.env` & `agents-cli-manifest.yaml`: Environment and deployment metadata.

### 4. Deployment & Compatibility Standards
- When deploying to **Agent Runtime** (`--deployment-target agent_runtime`):
  - Do NOT pass `--service-account` when `--agent-identity` is enabled (Agent Runtime uses `AGENT_IDENTITY`).
  - Serving routes are mounted automatically by `get_fast_api_app` and `attach_reasoning_engine_routes(app)` to ensure 100% compatibility with the Vertex AI Console Playground, `agents-cli run --mode adk`, and `agents-cli playground`.
